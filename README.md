# Algo trading system: engineering case study

A single-page, scroll-driven case study presenting the equity execution engine, the real-time relay, the operations desk and the mobile alerts app as one product. Static Next.js (App Router), no backend.

```bash
npm install
npm run dev      # http://localhost:3000
npm run build    # static prerender
npm run lint
```

## The shape of the page

The page is framed as a **build log in eight chapters**, so the order is the order the system was built in rather than the order a reference document would use: the rule comes before the wiring, and what broke comes before what was drawn to stop it breaking again.

| | Chapter | Section |
|---|---|---|
| 01 | First, one process | What it is, and what it is not |
| 02 | Then, a rule | Entry, ratchet, exit |
| 03 | Then, the walls | Seven layers between a signal and an order |
| 04 | Then it broke | Six things that were harder than they look |
| 05 | Then, the wire | Four services, one room |
| 06 | Then, the room | The desk and the phone |
| 07 | Then, the audit | What the repos actually contain |
| 08 | Still unproven | What is still unproven |

The chapters live in the `sections` array in [`src/content/caseStudy.ts`](src/content/caseStudy.ts). Each has an `id` (`ch1` … `ch8`, the anchor and the reading order) and a `slug` (`overview`, `trade`, …, the stable name components look themselves up by, via `sectionBySlug`). **To reorder the log, reorder that array and reorder the components in `src/app/page.tsx` to match**; nothing else refers to chapter positions. The contents list, the rail ticks and the rail's chapter label all read the array.

## Editing copy

Every word on the page lives in [`src/content/caseStudy.ts`](src/content/caseStudy.ts). Components render that file and contain no prose. A stat whose `value` is `null` is not rendered, so a figure the repos cannot supply never shows as a blank tile — it is named in a line under its group instead. Ordinals that are page chrome rather than copy (service cards, trade phases, the "next" list) are derived from array position by `src/lib/ordinal.ts`, so reordering the copy renumbers the page.

Data committed for the animations:

| File | What it is |
|---|---|
| `src/data/tape.json` | NSE daily bhavcopy, 7 Sep 2026, the 40 most-traded EQ-series symbols by turnover. Used by the hero ledger. |
| `src/data/bars.json` | One symbol's 15-minute bars for one session plus warm-up bars, entry and exit. **Currently provisional**: a synthetic intraday path inside a real day's open, high, low and close, generated by `node scripts/make-provisional-bars.mjs`. Replace it with a real export in the same shape and set `provisional: false`; the page switches its caption automatically. |

Shape of `bars.json`:

```json
{
  "symbol": "NSE:XXXX-EQ",
  "date": "2026-09-03",
  "provisional": false,
  "warmup": [{ "t": "09:15", "o": 0, "h": 0, "l": 0, "c": 0 }],
  "bars":   [{ "t": "09:15", "o": 0, "h": 0, "l": 0, "c": 0 }],
  "entry":  { "t": "10:00", "price": 0 },
  "exit":   { "t": "13:45", "price": 0, "reason": "trailing_stop" }
}
```

`warmup` is optional but should hold at least 20 prior bars so Supertrend(20, 1) and ATR(14) are seeded, as the engine seeds them from history. `entry` and `exit` are optional; when absent the page uses the first long Supertrend flip in the session and simulates the trailing stop on bar closes with the engine's arithmetic (`src/lib/indicators.ts`). `buildModel` in that file assembles the chart model; `src/lib/tradeChart.ts` turns it into geometry once, so scrubbing costs no arithmetic per frame.

## Visual system

A dark ink ground (`#0f0f0d`, raised to `#131311` on alternating chapters) with warm off-white text (`#ece9e0`), hairline rules at 13 % white, and **one** accent: amber `#e2a54b`. Green `#8bbf7a` and red `#e0705f` are reserved for market direction and for failure-versus-fix, never for decoration. The desk recreation keeps its own terminal palette (`--desk-*`) because it is a screenshot of another product, not part of this page's system.

Bricolage Grotesque carries display and text, with its width and optical-size axes loaded: chapter titles run at `wdth 88`, the hero at `wdth 82` / `opsz 96`, the closing statement at `wdth 85`. IBM Plex Mono carries every label, value, code path and figure that has to line up. Nothing is rounded — no border radius anywhere except the phone mock, which is a device. Tokens live at the top of [`src/app/globals.css`](src/app/globals.css).

The left gutter (`--gutter-l`) clears the fixed rail at every width, so the rail's chapter ticks line up with the body text regardless of which chapter is on screen. Below 768 px the rail is hidden and both gutters collapse to 1.5 rem: the rail needs a 3.5 rem column of its own and there is not one to spare at phone width. The contents list is the chapter nav there.

## Motion

Every tween uses one of four named cubic-beziers registered in [`src/lib/motion.ts`](src/lib/motion.ts): `reveal` (0.165, 0.84, 0.44, 1), `wipe` (0.77, 0, 0.175, 1), `settle` (0.33, 1, 0.68, 1) and `snap` (0.34, 1.56, 0.64, 1). Nothing uses a stock ease. All DOM animation is transform and opacity, plus SVG `stroke-dashoffset` for the self-drawing diagram edges. There are no canvases.

Scroll-driven work writes straight to the DOM from a single ScrollTrigger `onUpdate` per effect, so scrolling never re-renders React.

### 02 Then, a rule (`src/components/sections/Trade.tsx`)

| Animation | Trigger | Detail | How to disable |
|---|---|---|---|
| Sticky stage | Scrolling a 340 svh track | CSS `position: sticky`, not a ScrollTrigger pin, so touch behaves identically. | Remove the `trade-track` / `trade-stage` classes. |
| Scrubbed timeline | Track progress | One bar index per frame drives everything: candles pop in (`scaleY 0 → 1`) at their index, a `clipPath` rect widens so the Supertrend and the stop reveal in lockstep, the entry and exit markers pop with `snap` at their bars, the ratchet carets appear where the stop tightened, and the readout and the four phase captions follow the current bar. The chart arithmetic (`src/lib/indicators.ts`) mirrors the engine: Wilder ATR(14), TradingView-exact Supertrend(20, 1) on hl2, and a stop that is `max(previous, close − 1.5 × ATR)` with a two-tick floor, filled one tick worse than the breach. The price axis is fixed over the whole session so it never rescales mid-scrub.

### Cleanup

Every effect either runs inside `gsap.context()` and reverts it on unmount, or kills its ScrollTriggers and tweens explicitly. SplitText instances are reverted. The ledger clears its timeout. Lenis is destroyed and removed from the ticker. Refresh listeners are removed. Nothing survives unmount.

### Reduced motion

`prefers-reduced-motion: reduce` is checked before any effect is scheduled (`src/lib/motion.ts`), and reactively where a component needs to re-render on the change (`src/lib/useReducedMotion.ts`). When set: no SplitText, no timelines, no scrubs, no pins, no Lenis, no ledger roll, no scramble — and the `.js-reveal` visibility gate in `globals.css` is bypassed so every element is visible immediately. The trade chart renders fully drawn, the strategy stack becomes a horizontal scroller, and the rail still tracks position.

The page is complete with JavaScript disabled as well: `data-js` is stamped on `<html>` before hydration, and elements are hidden for animation only when that attribute exists.

## Verification

Checked against a production build (`next build` + `next start`) with headless Chromium, scrolling the full page at 1440 × 900, at 390 × 844, and with `prefers-reduced-motion: reduce`:

- No console errors, warnings or page errors in any of the three passes.
- No horizontal overflow at 1440 px or 390 px.
- The rail's thread, dot and clock track scroll from 09:15 to 15:30; the chapter label and the lit tick follow the chapter on screen; exactly one problem-index dot is lit at a time.
- The trade scrub reaches every bar, and the readout, stop and phase captions follow it.
- Under reduced motion the pin and the scrub are gone, the chart renders complete, and no element is left hidden.

`npm run lint` and `npm run build` are clean. Lighthouse was not re-run for this redesign; the figures quoted in earlier revisions of this file described the previous implementation and have been removed rather than carried over.
