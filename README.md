# Algo trading system: engineering case study

A single-page, scroll-driven case study presenting the equity execution engine, the real-time relay, the operations desk and the mobile alerts app as one product. Static Next.js (App Router), no backend.

```bash
npm install
npm run dev      # http://localhost:3000
npm run build    # static prerender
npm run lint
```

## Editing copy

Every word on the page lives in [`src/content/caseStudy.ts`](src/content/caseStudy.ts). Components render that file and contain no prose. A stat whose `value` is `null` is not rendered, so a figure the repos cannot supply never shows as a blank tile. The section order, ids and colour themes are the `sections` array in the same file.

Data committed for the animations:

| File | What it is |
|---|---|
| `src/data/tape.json` | NSE daily bhavcopy, 7 Sep 2026, the 40 most-traded EQ-series symbols by turnover. Used by the hero mosaic and the floor ticker strip. |
| `src/data/bars.json` | One symbol's 15-minute bars for one session plus warm-up bars, entry and exit. **Currently provisional**: a synthetic intraday path inside a real day's open, high, low and close, generated by `node scripts/make-provisional-bars.mjs`. Replace it with a real export in the same shape and set `provisional: false`; the page switches its caption automatically. |

Shape of `bars.json`:

```json
{
  "symbol": "NSE:XXXX-EQ",
  "date": "2026-09-03",
  "provisional": false,
  "warmup": [{ "t": "09:15", "o": 0, "h": 0, "l": 0, "c": 0 }],
  "bars":   [{ "t": "09:15", "o": 0, "h": 0, "l": 0, "c": 0 }],
  "entry":  { "t": "10:00", "price": 0 },
  "exit":   { "t": "13:45", "price": 0, "reason": "trailing_stop" }
}
```

`warmup` is optional but should hold at least 20 prior bars so Supertrend(20, 1) and ATR(14) are seeded, as the engine seeds them from history. `entry` and `exit` are optional; when absent the page uses the first long Supertrend flip in the session and simulates the trailing stop on bar closes with the engine's arithmetic (`src/lib/indicators.ts`).

## Visual system

Editorial rather than terminal: an ivory ground (`#faf9f5`, `#f0eee6`) with near-black ink (`#141413`), warm grey rules, and one text-safe accent per section (clay `#b8552f`, sky `#3f6f9e`, amber `#85480c`, olive `#5b6f42`) with pastel tints for surfaces. Headlines and prose are set in Newsreader, a text serif with optical sizing; UI labels use Geist; values and captions use JetBrains Mono. Surfaces are soft (8–16 px radii), buttons are ink pills with an arrow, figures carry a small sans title above and a serif caption below, and the opening statement has a drop cap. Tokens live at the top of `src/app/globals.css`; each section theme only shifts `--bg`, `--bg-2` and `--accent`.

## Animations

Every tween uses one of four named cubic-beziers registered in [`src/lib/motion.ts`](src/lib/motion.ts): `reveal` (0.16, 1, 0.3, 1), `wipe` (0.76, 0, 0.24, 1), `settle` (0.22, 1, 0.36, 1) and `snap` (0.34, 1.56, 0.64, 1). Nothing uses a stock ease. The only linear rates on the page are continuous motion or scroll-scrubbed progress, never a transition: the tape marquee, the pulses along diagram edges, and the scrub-driven clip, progress bar and horizontal track.

All DOM animation is transform and opacity, plus SVG `stroke-dashoffset` for the self-drawing diagram edges. Two canvases exist: the hero's WebGL field (GPU-side, one draw call) and the strategy funnel (Matter.js stepping a small world, drawn with Canvas 2D). Both render only while on screen. Section colour themes change via CSS variables on `<html data-theme>` with a `background-color`/`color` transition on `body`; that is the only other non-transform property that animates.

### Cleanup

Every effect runs inside `gsap.context()` (or `gsap.matchMedia()`) and reverts it on unmount, which kills every tween and ScrollTrigger it created. SplitText instances are reverted. The tape clears its timeouts and interval. Lenis is destroyed and removed from the ticker. Nothing survives unmount.

### Reduced motion

`prefers-reduced-motion: reduce` is read reactively (`src/lib/useReducedMotion.ts`). When set: no SplitText, no timelines, no ScrollTriggers, no Lenis, no marquee, no pulses, no magnetic drift, no pin, and the `.js-reveal` visibility gate in `globals.css` is bypassed so every element is visible immediately. The page is complete with JavaScript disabled as well: `data-js` is stamped on `<html>` before hydration, and elements are hidden for animation only when that attribute exists.

## Verification

Checked on 10 September 2026 against a production build (`next build` + `next start`) with headless Chrome:

- No console errors or hydration mismatches on desktop (1440 × 900), mobile (390 × 844) or with `prefers-reduced-motion: reduce`.
- No horizontal overflow at 390 px.
- Lighthouse desktop preset, with the WebGL field and the physics funnel in place: performance 96–98 across runs (total blocking time 110–140 ms; the renderer mounts only after first interaction, the physics library only near its figure), accessibility 100, best practices 100, SEO 100.
- Lighthouse mobile (simulated slow 4G, 4× CPU): performance 66, accessibility 100, best practices 100, SEO 100. Below-fold sections are code-split with `next/dynamic` (server rendering kept) so the hero hydrates first.

Cleanup is verified by construction: every effect returns a `gsap.context().revert()`, `gsap.matchMedia().revert()`, or explicit `kill()`.
